## Plain-language root causes and corrections

1. **Purpose was missing from personal cache identity.** A public-guidance request could store a graph-free private cache entry that a later causal request reused. The reverse order could expose a graph path to public guidance. Both public and personal keys now bind the canonical policy ID, policy version, purpose and required support; the personal key also binds the allowed personal-context kinds.
2. **Candidate limit was missing from both cache identities.** A max-1 request fetched and cached only two component candidates, so a later max-5 request reused a truncated set. Both keys now include the effective `max_candidates` value.
3. **The policy model trusted a Boolean claim.** A caller could set `trusted_server_created=true` while fabricating the policy ID, support requirements or contexts. `RetrievalGateway.retrieve()` now accepts only a trusted purpose enum and constructs the policy itself. `EvidenceRequirementPolicy` also validates every field against one canonical purpose/domain mapping.
4. **Individual models were valid while their combination was contradictory.** `EvidencePacket` and `RetrievalResult` now enforce agreement across policy, answerability, abstention, trusted scope, effective journey, request ID, state version, journey relation and component trace fields.
5. **Conflict relevance depended on knowing a proposed value or typing “conflict.”** Conflict and missing-information relevance now maps singular/plural terms and typed fields to personal categories. Generic allergy, restriction, medication, condition, appointment and journey questions surface matching unresolved state. Category restrictions remain policy-bound, so an appointment conflict does not block unrelated movement guidance.
